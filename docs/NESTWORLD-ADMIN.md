# NestworldCore — довідник адміністратора

Один спільний світ в одній JVM, порізаний на region-потоки. Цей файл —
коротка довідка по командах, конфіг-прапорцях і файлах стану. Архітектуру й
план див. у [ROADMAP.md](../ROADMAP.md).

## Команди (`/nestworld …`, права рівня 2+)

| Команда | Дія |
|---|---|
| `status` | Активні регіони: межі, вартість (мс), к-сть ентіті, deferred, heat-хотспоти; серверний MSPT/TPS |
| `borders` | Перемкнути візуалізацію кордонів регіонів частинками (END_ROD, радіус 96) |
| `split <id>` | Примусово розрізати регіон (ручні спліти пінуються — не зливаються авто) |
| `merge <a> <b>` | Злити два сусідні (siblings у BSP) регіони |
| `pins` | Показати всі піни (типи ентіті / типи BE / неймспейси модів) |
| `pin <type>` | Пінити тип ентіті **або** BE на main-потік (авто-визначення) |
| `unpin <type>` | Повернути тип на region-потоки |
| `pinmod <ns>` | Пінити **всі** ентіті й BE неймспейсу (зламаний мод цілком) |
| `unpinmod <ns>` | Зняти пін з неймспейсу |
| `spark …` | In-game spark через standalone-агент (лише коли мода spark немає) |

**Пінінг** — escape hatch сумісності: тип/мод, що не thread-safe, тікається на
main-потоці точно як у ваніли (паритет ціною паралелізму цього типу). Ефект із
наступного тіку. Нуль накладних витрат, коли нічого не запінено.

## Конфіг-прапорці (`-Dnestworld.*`)

Передавати JVM-у. У dev-сервері через gradle — найнадійніше через
`JAVA_TOOL_OPTIONS="-Dnestworld.x=y"`.

| Прапорець | Деф. | Призначення |
|---|---|---|
| `layoutSaveIntervalTicks` | `6000` | Період пере-збереження розкладки регіонів (тіків); пише лише при зміні топології |
| `timingLog` | `true` | Фазовий тайминг-лог раз/200 тіків; `false` глушить у проді |
| `autoPin` | `false` | Авто-пінити тип ентіті, що повторно крашить region-потік |
| `autoPinThreshold` | `20` | К-сть помилок типу до авто-піну |
| `regionEntityBudgetMs` | `40` | Бюджет ентіті-раунду регіону (мс); решта — round-robin на наступний тік. НЕ ставити <25 (поріг сплітів) |
| `maxMinecartPush` | `8` | Кап O(n²)-колізій вагонеток (точкові хотспоти) |
| `maxEntityPush` | `8` | Те саме для човнів/живих мобів (для мобів ефективний ліміт = maxEntityCramming) |
| `cutHeatWeight` | `0.15` | Вага block-tick щільності у скорингу ліній розрізу |
| `beTracePos` | — | `x,y,z`: трасувати збір/виконання конкретного BE (діагностика) |
| `spark.jar` | — | Шлях до spark-standalone-agent.jar для SparkBridge |

## Self-test / дев-прапорці

| Env / `-D` | Дія |
|---|---|
| `NESTWORLD_AUTOSPLIT=<tick>` | Форс-спліт на тіку N, мердж +600 (повний цикл) |
| `NESTWORLD_RANDOMTICK_TEST=<speed>` | Гнати random ticks у чанк (0,0) (ваніла гейтить на гравця) |
| `NESTWORLD_CUT_TEST` / `-Dnestworld.cutTest` | Детермінований тест скорера розрізів |
| `NESTWORLD_AUTOPIN_TEST` / `-Dnestworld.autoPinTest` | Тест порогу авто-піну |
| `NESTWORLD_LAYOUT_TEST` / `-Dnestworld.layoutTest` | Round-trip тест серіалізації BSP-дерева |

Усі self-test'и логують `[… SELF-TEST] PASS/FAIL` при старті.

## Файли стану (`<world>/data/`)

| Файл | Вміст |
|---|---|
| `nestworld-regions.dat` | Збережене BSP-дерево (NBT). Сервер стартує одразу в цю топологію — без cold-start фризу. Відсутній/битий → fallback на 1 регіон |
| `nestworld-pins.txt` | Запінені типи ентіті (один registry-id на рядок, людино-редаговано) |
| `nestworld-be-pins.txt` | Запінені типи block entities |
| `nestworld-pinned-mods.txt` | Запінені неймспейси модів |

Текстові піни-файли можна редагувати вручну (застосуються при старті) або через
команди (записуються одразу).

## Безпечна зупинка (важливо для важких паків)

На важкому модпаку `stop` іноді доводить сервер до збереження світу й друку "Stopped",
але сам JVM-процес не виходить — тримає пам'ять, поки не вб'єш вручну. Причина: JVM
виходить лише коли всі **не-daemon** потоки завершились, а якийсь мод міг створити
`ExecutorService`/`Timer` і не зупинити його на `FMLServerStoppingEvent`. Це проблема
конкретного мода, не ядра — але непередбачувано, який саме з сотень модів винен.

Рекомендований підхід — зупиняти з таймаутом і примусовим убивством:
```bash
rcon_send stop   # твій спосіб надіслати "stop" (RCON/screen/tmux stdin)
deadline=$(( $(date +%s) + 60 ))
while kill -0 "$PID" 2>/dev/null; do
    if [ "$(date +%s)" -ge "$deadline" ]; then
        jstack "$PID" > "hang-$(date +%Y%m%d-%H%M%S).txt" 2>&1 || kill -3 "$PID"
        kill -9 "$PID"
        break
    fi
    sleep 2
done
```
`jstack`/`kill -3` перед примусовим убивством — не пропускай цей крок: він виводить повний
дамп потоків, з якого одразу видно, ЯКИЙ саме потік (і, за назвою пакета, який мод) блокує
вихід. Без цього дампу причина лишається здогадкою назавжди.
